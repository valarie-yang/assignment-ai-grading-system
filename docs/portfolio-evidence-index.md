# Portfolio evidence index

## Recruiter path

1. Read the [product brief](product-brief.md) for the user problem and scope.
2. Follow the [architecture and state model](architecture-and-state-model.md) to see the workflow boundaries.
3. Review the [AI boundary](ai-boundary.md) for structured output, teacher control, and release gates.
4. Use the [demo script](demo-script.md) to walk through submission → assessment → review → release.
5. Read the [evaluation plan](evaluation-plan.md) and [limitations](limitations.md) to separate evidence from proposal.
6. Check [public release](public-release-checklist.md), [data classification](data-classification.md), and [threat model](threat-model.md) for governance judgment.

## Evidence status

| Evidence | Status |
|---|---|
| Product workflow and state model | Public, curated |
| AI output and human-review boundary | Public, curated |
| Synthetic demonstration narrative | Public-safe design evidence |
| Local offline MVP verification | Verified in separate private/local implementation; not mirrored here |
| Production model quality and scale | Not claimed |
| Real user or institution outcomes | Not claimed |

This index intentionally connects public product evidence without exposing the private implementation, real inputs, or operational configuration.
